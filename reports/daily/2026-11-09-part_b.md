## 2. 厳選事例（4件）

### 事例1: ESA Copernicus Sentinel衛星オープンデータとGoogle Earth EngineのGASオーケストレーション
- **概要**: [Automating Sentinel-2 Satellite Vegetation Index Pipelines via Apps Script and Earth Engine](https://developers.google.com/earth-engine/guides/apps_script) (ESA Earth Observation Community & Google Workspace Developer Relations)
  - 欧州宇宙機関（ESA）が公開するSentinel-2衛星の多重スペクトルオープンデータを、Google Apps ScriptをトリガーとしてGoogle Earth Engine API経由で定期取得・解析するパイプライン。
- **技術構成・アーキテクチャのポイント**:
  - **二段階非同期ETL**: 大規模な地理空間ラスター演算（NDVI植生指標の時系列差分計算）はEarth Engineの分散クラスタ側で実行させ、GASは計算完了タスクの監視（`poller`）とメタデータ（GeoJSON / 統計数値）のみをGoogleスプレッドシートへ格納。
  - **実行時間制限の回避**: 実行時間が数十分に及ぶ衛星解析ジョブに対し、GAS側の時間主導型トリガー（Time-driven Trigger）を用いて10分間隔でステータスチェックを行う分散ステートマシン構成を採用。
- **具体的な応用アイデア**:
  - 自治体や農業協同組合における耕作放棄地の自動検知、または森林・河川の環境変化モニタリングツールの低コスト構築。

### 事例2: WebAssembly（Rust/Wasm）を用いたHtmlServiceサイドバーでのクライアント側高速データ暗号化
- **概要**: [Zero-Knowledge Client-Side Encryption in Google Sheets using WebAssembly](https://github.com/googleworkspace/solutions) (Martin Hawksey & Community Contributors)
  - スプレッドシート内の機密データを、Googleのサーバーを経由する前にユーザーのブラウザ（`HtmlService` サイドバー）内でエンドツーエンド暗号化（AES-256-GCM）してからセルに保存するアーキテクチャ。
- **技術構成・アーキテクチャのポイント**:
  - **RustからWasmへのコンパイル**: 暗号化・復号処理をRustで実装し、`wasm-bindgen` で単一のBase64エンコード済みJavaScriptファイルとして `HtmlService` にインライン埋め込み。
  - **V8ランタイム負荷のゼロ化**: 重い暗号演算をクライアント側のブラウザスレッドで実行させることで、GASサーバー側のCPU時間消費を完全に回避し、大量行の一括処理を実現。
- **具体的な応用アイデア**:
  - 医療機関・教育機関における個人情報保護スプレッドシートの運用や、監査要件の厳しい企業内データ管理。

### 事例3: Cloud Run Sandboxes（Python）とGASによるPandas非同期バッチクレンジング
- **概要**: [High-Speed Data Wrangling for Google Sheets: Offloading Pandas to Cloud Run](https://cloud.google.com/blog/topics/developers-practitioners) (Google Cloud Architecture Center)
  - 数十万行に及ぶ不整合なオープンデータCSVを、GASの `UrlFetchApp` 経由でGoogle Cloud Run（Python / Pandas / Polars）へストリーミング送信し、1秒未満で構造化して返すハイブリッド構成。
- **技術構成・アーキテクチャのポイント**:
  - **IDトークン自動インジェクション**: `ScriptApp.getIdentityToken()` を利用してCloud Runへのセキュアなサービス間認証（OIDC）をノーコードで実現。
  - **メモリ上限突破**: Googleスプレッドシートのスクリプト実行時メモリ制約（100MB）を気にせず、Cloud Run上の大容量コンテナ（2GB〜4GB）でPolarsによる並列集計を実行。
- **具体的な応用アイデア**:
  - 政府統計（e-Stat）や自治体の数万行におよぶオープンデータCSVの自動定期クレンジングと集計台帳の更新。

### 事例4: Webhook駆動型Pub/Sub連携によるGmailリアルタイムPushトリガー
- **概要**: [Eliminating Polling: Event-Driven Google Workspace Automation with Cloud Pub/Sub](https://medium.com/google-cloud) (Romain Vialard & Workspace GDE)
  - 定期実行トリガーによる数分ごとのGmailポーリングを廃止し、Gmail APIの `watch()` とGoogle Cloud Pub/Sub、GASのWeb Apps（`doPost`）を直結したイベント駆動アーキテクチャ。
- **技術構成・アーキテクチャのポイント**:
  - **クォータ消費の90%削減**: 定期ポーリングによるAPI呼び出しをゼロにし、メール受信の瞬間にPub/SubからGAS WebhookへPush通知を送出。
  - **PropertiesServiceによる重複排除**: Pub/Subの「At-least-once（最低1回配信）」特性に対し、`historyId` を `PropertiesService` のキャッシュキーとして利用し、多重実行を防止するロック機構を実装。
- **具体的な応用アイデア**:
  - 問い合わせメールの即時チケット化、請求書添付メールのDrive自動仕分け・OCR連携。
